## Findings

### F1 — should-fix — a provider's error body reaches the row verbatim except for keys, including emails and org ids (§6)

`probe_model` sets `r.error = redactor.redact_error(h.body.trim())` for every non-2xx (`src/probe.rs`). The redactor
scrubs known secret values and the `sk-`/`ghp_`/`Bearer ` patterns, and nothing else. §6 says a record **MAY NOT
reveal** "a raw error body, an email or org id unless the operator typed it as the label". Real provider errors carry
these. For example, OpenAI's 429 text names `organization org-…`.

Command: a stub at 127.0.0.1:4298 (`stub.py`) answers 401 with a body that contains the fake email `jane.doe@example.com`
and the fake org id `org-FAKEorg1234567890`. Then `QB_RV_FAKE_KEY=fake-not-a-real-key-000 quotabus probe --config
file.toml`, and `python3 -c '…print(r["error"])'` on the row:
```
probe rc=0
state: auth_failed
error: {"error":{"message":"Incorrect API key provided. You can find your key at https://platform.example/account. Account owner jane.doe@example.com, organization org-FAKEorg1234567890.","type":"invalid_req
```
The row goes on the shared bus and into `status --json`, which is the output people paste.

**Fix:** stop putting the body text in the row. Write a structured summary: `http_<status>` plus the provider's
machine-readable `error.type` / `error.code` when it parses, else the first N chars after scrubbing. Add email
(`[^\s@]+@[^\s@]+`) and `org-[A-Za-z0-9]+` pattern scrubs to `Redactor`. Add a test with a body that carries an email
and an org id, with a control.

### F2 — should-fix — there is no `publish_balance` switch, and `publish_balance = false` is silently ignored, so the balance is still published (§6, §10 Q3)

§6: a record may reveal "a balance **when `publish_balance = true`**". §10 Q3: "`publish_balance` stays a per-service
switch for outsiders". The item's release comment says SIG-002 was built with "publish_balance per service". The code
has no such field: `grep -rn publish_balance src/ examples/ tests/` matches only `docs/DESIGN.md:224,276`.
`raw::Service` lacks `#[serde(deny_unknown_fields)]`, unlike `Bus`, `FileTable` and `Probe`
(`sed -n 150,218p src/config.rs | grep -n deny_unknown` gives lines 8, 15 and 21 only, and nothing on `struct Service`
at line 49). So an operator who opts out gets no error, and the balance is still written to every row.

Command: `pb2.toml` is a minimal `[file]` config whose `[[service]]` has `publish_balance = false`. Then `quotabus status
--config pb2.toml`:
```
SERVICE  MODEL  STATE    AGE  SOURCE  DETAIL
x        m      UNKNOWN  -    -       absent
rc=0
```
The config was accepted, and the key has no effect. `probe_service` sets `r.balance = Some(bal.clone())`
unconditionally.

**Fix:** add `publish_balance: bool` per service. Its default follows the §10 Q3 recommendation. When it is false,
`balance` is not put on the row; the floor still applies to `state`. Add `deny_unknown_fields` to `raw::Service`, or
reject unknown service keys explicitly, so a typo'd privacy switch is an error. Add tests for both values.

### F3 — should-fix — an unreadable row, or a failed `get` while listing, reads `UNKNOWN absent` instead of CANNOT-ASSESS (§2)

`NatsKv::list` and `FileBackend::list` log `skipping unreadable row` and drop the key. The freshness rule then calls the
key `absent`, which says "no row exists". Here a row exists and could not be read: "a measured failure to measure".
For `NatsKv`, every `store.get` error is wrapped as `BackendError::Other`, and `list` skips `Other`. So a transient
get failure (a request timeout) part-way through a listing also reads `absent` with rc 3, not CANNOT-ASSESS with rc 2.

Command: `echo 'not json' > rows/api.fakeprov.acct.m1.json; quotabus status --config file.toml --check fakeprov`:
```
… WARN quotabus::backend: skipping unreadable row: /tmp/rv-exp001-scratch/rows/api.fakeprov.acct.m1.json is not a row: expected ident at line 1 column 2
SERVICE   MODEL  STATE    AGE  SOURCE  DETAIL
fakeprov  m1     UNKNOWN  -    -       absent
rc=3
```
**Fix:** have `list` return the unreadable keys alongside the rows, for example `(rows, unreadable: Vec<(key,
reason)>)`. `status` then gives such a key `CannotAssess { reason: "cannot_assess:unreadable_row" }`. Classify a
`store.get` request error as `Unreachable`, not `Other`. Add a test with a corrupt row and a control.

### F4 — nit — on the file backend, a missing row directory reads as "no rows" (`UNKNOWN absent`, table rc 0), not the §2 "bucket missing → CANNOT-ASSESS"

`FileBackend::list` returns `Ok(Vec::new())` on `NotFound`. Command: `quotabus status --config file.toml`, with
`rows/` not yet created:
```
SERVICE   MODEL  STATE    AGE  SOURCE  DETAIL
fakeprov  m1     UNKNOWN  -    -       absent
rc=0
```
`--check fakeprov` gives rc=3. This is not a false `ok`, but a reader pointed at the wrong directory (a typo'd `[file]
dir`) cannot tell that from "never probed". **Fix:** a missing directory on a READ should be
`BackendError::BucketMissing(dir)`, giving CANNOT-ASSESS with rc 2. The writer already creates the directory.

### F5 — nit — the OpenAI probe uses chat completions, where §4 names the responses API

§4's row says "responses-API call with a 20-token ceiling on `gpt-5.6-sol`". `probe_model` posts `{base}/chat/completions`
with `max_completion_tokens`. Command: `grep -n 'chat/completions\|max_completion_tokens' src/probe.rs`. Mini's bus
shows the call works (`openai gpt-5.6-sol ok 4m official`), so this is only a design drift to record. **Fix:** a line
in the PR body or the item saying the chat probe was chosen and why, or a follow-up to update §4.

### F6 — nit — the plist logs to world-readable `/tmp`, and the PR body publishes the account balances on a public repo

- **Plist:** `packaging/launchd/com.congruentsys.quotabus-probe.plist` sets `StandardOutPath` /
  `StandardErrorPath` under `/tmp/`. The output is redacted, so this is hygiene, not a leak. Prefer
  `~/Library/Logs/quotabus/`.
- **PR body:** `gh pr view 2 --json body -q .body | grep -nE '[0-9]+\.[0-9]+ (CNY|USD)'` matched lines 25–26 (amounts
  omitted here). §6 lets a record reveal a balance on the bus, but a GitHub PR is public, and SIG-002 (publish
  balances) is still the Captain's open question. **Fix:** replace the amounts with "above floor" / "below floor" in
  the PR body.
