## Findings

### F1 — should-fix: a config parse error prints the bus URL line, password included
Done-when says "no error, log or row ever contains the password", and the brief names `config` errors. `main.rs:66`
redacts a `Config::load` error with `Redactor::default()`, which does not know the bus password. The TOML error snippet
quotes the offending line, so the password is printed whenever that line, or the `url` value, is malformed. The bug
predates this PR (the same line is on `origin/main`), but it is inside this hazard's scope. A user who mistypes the
line gets their bus password on stderr or stdout, and quite possibly into a pasted bug report.
```
$ printf '[bus]\nurl = "nats://qbuser:fakeCfgPw9@127.0.0.1:4222" junk\nbucket = "qb_rv"\n' > bad1.toml
$ RUST_LOG=trace quotabus --config bad1.toml probe        # rc=1, fakeCfgPw9 count=1
quotabus: bad1.toml: invalid config: TOML parse error at line 2, column 49
2 | url = "nats://qbuser:<PW-LEAKED>@127.0.0.1:4222" junk
$ quotabus --config bad1.toml status --json               # rc=2, count=1
CANNOT-ASSESS: bad1.toml: invalid config: TOML parse error at line 2, column 49
2 | url = "nats://qbuser:<PW-LEAKED>@127.0.0.1:4222" junk
```
The same happens with an unterminated string (`bad2`, `invalid basic string`) and with a wrong type
(`url = ["nats://…"]`, `bad3`, `invalid type: sequence`). The output above was piped through
`sed 's/fakeCfgPw9/<PW-LEAKED>/'`.

**Fix:** give the Redactor a URL-userinfo pattern, so that even `Redactor::default()` scrubs any `scheme://user:pass@`
and token-form `scheme://tok@`. For example, replace the capture of
`([A-Za-z][A-Za-z0-9+.-]*://[^\s:/@"']*:)[^\s@"']+@` with `${1}***@`. That keeps the email regex from catching
`user@host`, and it covers every path, not only `main`. Add a red-first test: a malformed config with a credentialed
URL must not leak through `probe` or `status`, with a control showing that the checker sees the password in the
unredacted error.

### F2 — nit: comma-separated server lists never worked, and only the first server's credentials are used
`BusUrl::parse` splits on `,` and its doc comment promises list support, but `connect(bus.address.as_str())` passes the
joined string to async-nats, which rejects it. This also predates the PR:
```
$ leak.sh multiplain "nats://127.0.0.1:14322,nats://127.0.0.1:14322"
quotabus: cannot publish: bus unreachable: failed to parse server or server list: NATS server URL is invalid: invalid port number
```
There is no leak. **Fix:** connect with `Vec<ServerAddr>` parsed per server, or drop the list claim from the doc
comment. If lists stay, say that only the first server's credentials are used.

### F3 — nit: an unencoded `/`, `#` or `,` in a password gives "invalid port number"
The failure is safe: no leak, and CANNOT-ASSESS rc 2. But it does not tell the user what to do:
```
$ leak.sh slash "nats://qbslash:fakeSl/ashPw9@127.0.0.1:14322"
quotabus: cannot publish: bus unreachable: failed to parse server or server list: NATS server URL is invalid: invalid port number
```
The same output appears for `#` and `,`. With `%2F` the connection works (rc 0). Done-when allows "refused with a clear
config error". **Fix (optional):** when parsing fails and the URL has `://` but no `@` inside the authority, while an
`@` appears later, say "percent-encode reserved characters in the bus password". The message must not echo the URL.

### F4 — nit: no test guards `scrub()` in `connect()`
Mutation M3 (`scrub()` made the identity) left all 7 tests green, because the Redactor already masks the same text
downstream. **Fix:** add a unit test on the `BackendError::Unreachable` text from `NatsKv::connect_reader`, with a
credentialed URL to a closed port. Or drop `scrub()` as redundant.
