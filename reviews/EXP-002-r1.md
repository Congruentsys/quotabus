**F1 — nit: the `claude -p` fallback child inherits every environment variable that is not a configured secret.**
- Command: the fake-`claude` run in check 4. `UNCONFIGURED_SECRET` appears among the child's env names.
- Under `doppler run --project nusy-product-team`, the child therefore receives every project secret that this config
  does not name.
- The brief's bar ("no other configured secret") is met, and the child is Claude Code itself, run with a constant
  prompt and `--max-turns 1`. The exposure is still wider than it needs to be.
- `HOME` is passed through, so user-level `~/.claude` settings and hooks still apply to the child; only the project's
  are avoided, by `current_dir(temp_dir)`.
- Fix (a follow-up is fine): `cmd.env_clear()`, then pass an allowlist (`PATH`, `HOME`, `TMPDIR`, `USER`, `LANG`) plus
  `CLAUDE_CODE_OAUTH_TOKEN`. Add a test that plants an unconfigured variable and asserts that the child lacks it.
