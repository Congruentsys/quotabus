## Findings

**F1 (nit): the red is probabilistic, and the PR's "red on 3 of 3 runs" overstates it on this host.**
Command: `cargo test -q --locked --test haz002_fixture_stress`, run 10 times at `cf35bba`. Output: FAILED on runs
2, 5, 6 and 7 (1, 3, 1 and 2 of 144 first connects reset), ok on the other 6 (quoted in check 1). It is still a real
red, and 10/10 green at the tip makes a chance pass unlikely (≈0.6%). But one green run at the tip is weak evidence on
its own. Proposed fix: in the PR body or the item's closing comment, say "red on 4 of 10 runs on M5-MBP-2 (3 of 3 on
the author's runs)". Optionally raise `ROUNDS` so that a single run of the red fixture fails with high probability.

**F2 (nit): the 10 s bound can overshoot by up to about 3 s.**
Read `tests/common/mod.rs` `greets()`: `connect_timeout(…, 1s)` then `set_read_timeout(2s)`. The deadline is checked
only at the top of the loop, so a probe that starts just before the deadline can run about 3 s past it. The bound
still fails loudly (check 3: `not within 10s`, 10.006 s when no port is published). Proposed fix: cap both timeouts at
`deadline.saturating_duration_since(Instant::now())` (at least 1 ms), or say "about 10 s" in the
`NATS_READY_BOUND` doc comment.

**F3 (nit): the brief's leak check `pgrep -fl nats-server` matches the reviewer's own process.**
Command: `pgrep -fl nats-server` during the review. Output: two matches, PID 21371 (`/bin/zsh -c … cat > … brief …`)
and PID 21396 (`claude --model opus … -p # Review brief …`). No nats-server was running. Proposed fix: future pairit
briefs should use `pgrep -xl nats-server`, which matches the process name exactly.

**F4 (nit): the ports-file lookup assumes the binary on PATH is nats-server itself.**
`spawn_nats` reads `nats-server_<child.id()>.ports`. If `nats-server` on PATH were a wrapper script (an asdf or mise
shim, for example), the pid or basename would differ. Every start would then fail with
`not within 10s (no ports file yet)`. That failure is loud and not silent; this host has a real binary
(`file /opt/homebrew/bin/nats-server` → `Mach-O 64-bit executable arm64`). Proposed fix: optional. Read the only
`*.ports` file in the per-server `ports_dir`, which is already private to each server, instead of building its name.
